# 陀螺仪运行日志

这份工程已接入内存日志。烧录新生成的 HEX 后，车独立运行时自动记录，不需要接屏幕或电脑。日志只记录数值，不发送调试串口、不写 Flash、不增加等待。实际运行开销需要实车测量；导出的 JSON 会给出记录函数和采样函数内部的最大执行周期。

## 记录内容与范围

- 时间从 `main()` 中 `GyroLog_Init()` 开始计，单位为微秒，表格显示毫秒。
- 原始航向 `global_angle`、控制角度 `anglea`、Z 轴角速度、有效角度帧数和最新角度帧龄。
- 每次 `car()` 的开始及返回；`car(0)` 的目标、方向指令、进入容差、每个轮电机停车指令发送函数返回时刻。
- 调正返回后至少 50/200/500ms 的角度记录，使用原有 TIM2 定时中断采样，不阻塞或等待。采样时若下一动作已开始，表格的底盘模式会显示它，不能当作静止角度。
- 调正和调正返回后的 500ms 内约每 20ms 采样，其他时间约每 200ms 采样。
- 最终 `qidian()` 返回后记录完成，再由定时器采样约 500ms，自动冻结。测试入口若没有执行这个调用，日志继续运行，可以手动冻结。

停车记录说明的是“原发送函数返回”，不是电机收到命令、到位、确认或已经停稳。日志本身不改变控制判断，调正容差以 BSP/car.c 为准，本次保留用户当前的 ±0.4°。

日志占 49216 字节（约 48KB）。512 条事件按顺序保留，满后停止追加并统计丢弃数；1024 条角度采样循环保留最新部分，不承诺保存全程每一次采样。`gyro_log.header.events_dropped` 表示关键事件丢弃数，`sample_total` 大于 `sample_count` 表示早期采样已被覆盖。可以在 `hardware/gyro_log.h` 中调整容量，但扩大前需要重新检查内存。

## 跑完怎样接电脑读取

**保持小车供电，不按复位，不重新下载。内存日志断电会丢失，普通程序启动也会重新初始化它。**

当前工程的 Keil 配置原本启用了调试时下载程序及运行到 main。读取本次日志前，必须先配置“只连接，不复位、不重新下载”：

1. `Options for Target → Debug`：取消 `Load Application at Startup`、取消 `Run to main()`。
2. `Debug → Settings`：连接选择 `Normal`，取消 `Reset after Connect`，不要使用 `Connect under Reset`。不同 ST-Link 驱动版本界面名称可能略有不同。
3. 接 ST-Link/SWD，进入调试。观察 `gyro_log.header.frozen`，正常任务完成 500ms 后它为 1。程序已经冻结日志时，可以暂停 CPU。
4. 若车在某步卡住、`frozen` 为 0，在 Watch 中将 `gyro_log.header.frozen` 改为 1，让 CPU 继续运行一小会儿，再暂停。这样当前一次写入能完整结束；不要在写入到一半时立即导出。
5. 打开本目录 `导出命令.txt`，把其中一行 `SAVE gyro_log.hex ...` 复制到 Keil 的 Command 窗口执行。它保存的是运行后的 RAM，不是烧录用 `Template.hex`。
6. 在 Keil 工程目录 `PRJ` 找到 `gyro_log.hex`。双击本目录 `导出日志.bat`；也可以把该 HEX 拖到这个 BAT 上。电脑需有 Python。

生成的三个文件放在本目录：`gyro_log.csv`、`gyro_log_调正汇总.csv`、`gyro_log.json`。CSV 可用 Excel 打开，也可以发来分析。

`导出命令.txt` 的地址根据本次编译的 `PRJ/Listings/Template.map` 生成。如果之后改代码导致 RAM 地址变化，重新生成命令：

```powershell
python -X utf8 .\陀螺仪日志\gyro_log_decode.py --map .\PRJ\Listings\Template.map --save-command .\陀螺仪日志\导出命令.txt
```

第一次实车使用要确认连接过程没有让板子复位；主机测试及编译不能代替这项验证。本次没有自动烧录或连接实车。

## 开关与调试

在 `hardware/gyro_log.h` 把 `GYRO_LOG_ENABLE` 改为 0 后重新编译，即关闭日志并移除日志缓冲区。无需删除函数调用。两份桌面工程分别编译，分别保留自己的最新用户参数。

Keil 可观察 `gyro_log.header.event_count`、`sample_count`、`events_dropped`、`frozen`。日志最大耗时字段 `max_write_cycles` 和 `max_tick_cycles` 是运行时测得的函数内部 CPU 周期数，并非整套控制系统的最坏耗时。除以 `clock_hz`、再乘一百万得到微秒。

## 2026年10月14日调正收尾更新

car(0) 已加入接近目标时减速、停车后角度与角速度稳定检查，以及停稳后的补调。日志中同一次调正可能先后出现两个方向和多组停车命令；这属于补调，不能仅凭双方向标记认定为旧分支错误。

新编译的 RAM 地址已变化，导出新固件运行日志时使用本目录更新后的“导出命令.txt”。此前导出的 HEX 文件仍可直接解码，无需改动。

故障等待时可在 Keil 查看 car_heading_status：3为角度断流，4为调正超时，5为数据不合法。故障不会放行下一段路线。
