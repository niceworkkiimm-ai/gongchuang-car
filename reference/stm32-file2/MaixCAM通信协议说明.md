# MaixCAM 通信对接说明

更新日期：2026-09-15。此工程为 STM32F103ZE 标准外设库工程。

已将主控的摄像头接收协议改为指定的固定 8 字节格式，替换原来的 `A3 B3 x y` 接收方式。

**2026-09-16 更新：当前默认启动“原地识别红色并抓取一次”测试。** `main.c` 中发送模式 1，收到有效 found 后调用原抓放动作 `wuliao1()`，测试期间不执行路线。模式修改位置与测试步骤见 `2文件_通信抓取测试说明.md`。原路线及其内部视觉、抓放注释状态仍保留；下文视觉对准接口是独立能力，当前通信抓取测试不会调用它移动底盘。

## 1. 接线与串口

沿用本工程的 UART4，115200 波特率、8 位数据、无校验、1 位停止位：

| STM32 引脚 | 连接方向 |
| --- | --- |
| PC10 / UART4_TX | 接 MaixCAM 所用串口的 RX |
| PC11 / UART4_RX | 接 MaixCAM 所用串口的 TX |
| GND | 两端共地 |

MaixCAM 端的具体串口引脚由其程序决定，本工程未提供摄像头端源码。USART1 电机通信、USART3 陀螺仪通信保持原样。

## 2. MaixCAM → 主控：严格 8 字节

MaixCAM 每处理 10 个视觉帧发送一次。主控逐包接收，不再隔 10 包取一次，也不要求第 8 字节之后有换行或其他字段。

| 字节 | 含义 |
| --- | --- |
| Byte0 | `0xAA` 帧头 |
| Byte1 | found：`0x01` 找到，`0x00` 未找到 |
| Byte2 | dx 高字节 |
| Byte3 | dx 低字节 |
| Byte4 | dy 高字节 |
| Byte5 | dy 低字节 |
| Byte6 | `Byte1 ^ Byte2 ^ Byte3 ^ Byte4 ^ Byte5` |
| Byte7 | `0x55` 帧尾 |

dx、dy 按 **16 位有符号整数的补码，高字节先发** 解码。

```text
图像大小：320 × 240
图像中心：(160, 120)
dx = 目标 X - 160
dy = 目标 Y - 120
```

按图像坐标，目标在中心右边时 dx 为正，在中心下边时 dy 为正。摄像头安装方向与车体运动方向的对应关系需要实车核对。

可用串口工具按 HEX 发送以下测试帧：

```text
找到且位于中心：AA 01 00 00 00 00 01 55
未找到：        AA 00 00 00 00 00 00 55
dx=-20,dy=30：  AA 01 FF EC 00 1E 0C 55
```

未找到时，主控将本次偏移清零并标记无目标，不会把它当作已经对准。校验、帧尾或 found 字段错误的包被丢弃；接收器可以从噪声、断包、连续数据包中恢复。包内出现 `AA` 或 `55` 仍按数据处理。

## 3. 主控 → MaixCAM：模式选择

你提供了模式含义，但没有另外给出下行指令帧格式。本版采用 **一个原始数值字节 `0x00`～`0x07`**。摄像头端也应按这一方式接收；`0x01` 和字符 `'1'`（`0x31`）不同。

| 模式字节 | 识别内容 | C 常量 |
| --- | --- | --- |
| `00` | 不识别 | `MAIXCAM_MODE_OFF` |
| `01` | 红色物料 | `MAIXCAM_MODE_RED` |
| `02` | 黄色物料 | `MAIXCAM_MODE_YELLOW` |
| `03` | 蓝色物料 | `MAIXCAM_MODE_BLUE` |
| `04` | 绿色物料 | `MAIXCAM_MODE_GREEN` |
| `05` | 黑色物料 | `MAIXCAM_MODE_BLACK` |
| `06` | 浅蓝色物料 | `MAIXCAM_MODE_LIGHT_BLUE` |
| `07` | 圆环和数字 | `MAIXCAM_MODE_RING` |

调用 `MaixCAM_SetMode(mode)` 即发送一个字节，同时清除本地旧目标。非法模式不会发送。旧扫码字符串若保存字符 `'1'`～`'6'`，可通过 `MaixCAM_ColorFromAscii()` 转换为数值模式。

这 8 字节没有颜色编号、数字编号、转盘停止标记或模式回显。主控只能知道找到了目标及其偏移；模式 7 无法让主控读出“识别到了数字几”。旧代码的 `A4/A5/A6` 特殊事件不能直接由 found 取代为“可以抓取”。本版未实现六色分拣的完整任务流程。

协议也没有序号或模式确认，因此清除旧目标只能清除主控已经接收的数据，无法证明在途包属于切换后的模式。若需要严格区分目标身份或确认模式生效，需要摄像头配合补充约定。

以下数值按提供内容原样保存，顺序为 `[L_min, L_max, A_min, A_max, B_min, B_max]`。

| 物料 | LAB 阈值 |
| --- | --- |
| 红 1 | `[0, 80, 40, 80, 10, 80]` |
| 黄 2 | `[60, 71, -11, -4, 35, 120]` |
| 蓝 3 | `[4, 25, 4, 24, -42, -23]` |
| 绿 4 | `[19, 39, -30, -11, -13, 33]` |
| 黑 5 | `[0, 14, -4, 6, -11, 7]` |
| 浅蓝 6 | `[21, 38, -13, 4, -51, -18]` |

另存有 `MaixCAM_LAB阈值.json`。阈值在摄像头端用于识别，本 STM32 工程不会读取该 JSON。本文件夹没有 MaixCAM 程序，因此没有声称已在摄像头上应用这些阈值或发送周期。

## 5. 在代码中使用

仅接收识别结果时，进入该任务时选择一次模式，之后循环读取快照。不要每次读取都重新设置模式或调用 `fuwei()`，否则会反复清掉刚收到的目标。

```c
#include "uart_4.h"

/* 进入识别阶段时调用一次： */
MaixCAM_SetMode(MAIXCAM_MODE_RED);

/* 后续主循环中读取： */
MaixCAM_Target target;
if (MaixCAM_GetTarget(&target) &&
    MaixCAM_TargetFresh(&target, MaixCAM_NowMs(), MAIXCAM_LINK_TIMEOUT_MS))
{
    /* target.dx、target.dy 是摄像头原始偏移。 */
}
```

`MaixCAM_GetTarget()` 返回“收到过有效协议包”，不等于“当前有目标”，所以还要检查新鲜度与 found。`MaixCAM_TargetFound()` 已合并这些判断。`maixcam_found/dx/dy` 以及 `x/y/error_x/error_y` 用于调试观察；数据断流后这些全局变量不会自动清零，控制逻辑应使用带超时检查的接口。

当 found 有效时，兼容观察量为 `x=160+dx`、`y=120+dy`；沿用原定位方向的控制误差为 `error_x=-dx`、`error_y=-dy`。坐标 0 是合法图像边缘，不能用 `x==0` 判断未找到。

在指定位置执行视觉对准时使用 `openmv.h` 的接口，文件名为兼容旧工程而保留：

| 函数 | 范围和允许偏差 |
| --- | --- |
| `vision(mode)` | 模式 1～7，两个轴均在 ±2 像素内 |
| `WL_dingwei(color_mode)` | 物料模式 1～6，±5 像素 |
| `WL_dingwei2(color_mode)` | 物料模式 1～6，±8 像素 |
| `Vision_Align(mode, tolerance_px)` | 自定义允许偏差 |

这些函数是阻塞式接口，应从主循环或任务中调用，不能从中断调用。调用时先停止轮子、选择模式；只对新接收的包更新纠偏。成功需要连续收到两个不同数据包都满足允许偏差；同一个包反复读取不累计确认次数。

本版将旧摄像头专用的“像素乘固定系数转脉冲数”定位，改为按偏移方向低速纠偏：X 轴 5 RPM、Y 轴 7 RPM，每次优先调整 X 轴。轮号与转向组合沿用旧视觉微调代码。这属于定位实现的变更，需实车验证摄像头安装方向和收敛情况；未完成实车标定。

函数返回 `VISION_OK` 表示对准成功；其他状态为 `VISION_BAD_MODE`、`VISION_NO_TARGET`、`VISION_LINK_TIMEOUT` 或 `VISION_ALIGN_TIMEOUT`。结束时均发送四轮停止命令及模式 0。调用者必须根据返回值决定后续流程，失败不能继续抓放或直接跳到下一段路线。这里只提供定位结果，不自动操作夹爪。

当前 `task.c` 的注释区保留了旧抓放流程参考，并调整了接口名称和模式参数，但它们仍不是可直接整体取消注释的完整新流程；尤其需要重做旧事件等待、失败处理和目标身份判断。

## 6. 时间设置

`hardware/uart_4.h` 中可调整：

```c
#define MAIXCAM_LINK_TIMEOUT_MS 1000U
#define MAIXCAM_ALIGN_TIMEOUT_MS 15000U
#define MAIXCAM_ALIGN_CONFIRM_FRAMES 2U
```

计时来自现有 TIM2 的 20 ms 更新中断，`main.c` 中已加入 `MaixCAM_Tick20ms()`；独立调用接口前也要完成原工程的 `PWM_Init()`。如果以后修改 TIM2 周期，需要一起修改该计时接口。

摄像头每 10 个视觉帧发一次，实际间隔取决于视觉帧率。例如 30 FPS 时约 333 ms 一包，10 FPS 时约 1000 ms 一包。默认 1000 ms 的断流超时需要根据实际包间隔留出余量。无目标包在下一轮检查时结束对准；无数据则在超时后结束。四轮指令逐个发送，软件停止不代表已测得实际电机停转。

用 Keil 5 打开 `PRJ/STM32_UART_CMD.uvprojx`，执行 Rebuild All 后使用本次生成的固件。压缩包只包含源码、工程设置和说明，不包含旧 HEX、目标文件或旧编译缓存；原目录已有的 HEX 不能视为本次新代码的编译结果。

工程保留原来的 ARMCC 5.06 update 6 编译器选择。本机安装的是 update 5，因此验证时在独立副本中选用 ARMCC 5.06 update 5（build 528）。如果 Keil 提示所选编译器未安装，在 Options for Target → Target 中选择本机安装的 ARM Compiler 5，再重新编译。
