# 陀螺仪内存日志 · 2026-10-14

用户授权主要记录陀螺仪，便于小车脱离屏幕和电脑运行后再读取。两份桌面工程（小车只加通信版本、屏幕融合完成版）分别接入独立 `hardware/gyro_log.c/.h`，使用各自当前文件，未互相整体覆盖。记录原始角度、控制角度、Z 轴角速度、角度帧数/帧龄、底盘动作边界及调正停车时序。

新增日志文件及电脑导出工具；既有代码仅在 `APP/main.c`、`BSP/car.c`、`hardware/uart_3.c` 加观测调用，并在 uvprojx 注册两个日志文件。main 最终回程返回后请求完成，原有 HMI 完成调用仍保持次序。TIM2 原有角度赋值后做被动采样，不改定时器频率。所有控制条件、速度、脉冲、延时、路线、扫码、视觉和原始数据解析保留。既有源码可以逆向移除所加片段还原修改前字节，未整体转码。

固定格式：64 字节头、32 字节记录，512 个事件、1024 个循环采样，默认 RAM 占 49216 字节。关键事件满后保留早期记录并计数丢弃，采样保留最近部分。调正及返回后 500ms 每约 20ms 采样，其他阶段每约 200ms 采样；正常最终 qidian 返回后 500ms 冻结，不额外等待。后续采样可能落在下一动作期间，其底盘模式如实记录，不能当作停稳证明。发送记录不等于 motor ACK。

DWT 只启用和读取，不清零共享计数器。利用原有定时器持续维护无符号差值计时，可跨越 DWT 环绕；日志微秒计数也使用无符号差值。短临界区恢复调用前 PRIMASK，计数在完整记录之后发布。模块无动态内存、串口打印、Flash 写入、等待或电机控制。全量编译结果及总 RAM 占用见交付记录，硬件耗时验证尚待实车。运行时 `max_write_cycles`、`max_tick_cycles` 可供分析内部开销。

桌面工程内 `陀螺仪日志/使用说明.md` 说明 ST-Link 不复位连接、冻结、Keil SAVE 导出与 CSV 转换。当前 Keil 原配置在调试启动时下载并运行到 main，因此读取前需按说明取消自动下载/复位；本次没有改掉用户的调试配置，也没有烧录。

电脑工具 `tools/gyro_log_decode.py` 支持 Intel HEX、原始 RAM 二进制，校验数据与格式、还原采样环顺序，输出明细 CSV、调正汇总 CSV、JSON 元数据，并可从 map 生成 SAVE 地址。工程内复制了同一工具和 BAT 入口。`tools/tests/test_gyro_log.py` 对生产模块做时钟环绕、嵌套屏蔽、有限缓冲、采样及冻结测试，并验证电脑导出及坏数据拒绝。

关闭方法：`hardware/gyro_log.h` 的 `GYRO_LOG_ENABLE=0`，重新编译。关闭分支的调用和 RAM 缓冲均移除。

验证记录：两工程 ARMCC 5.06 update 5 全量重编译均为 0 错误、34 条原有警告，日志模块无新增警告，生成 HEX。主控总静态 RAM 为 54248 字节，融合版为 54296 字节，均在工程配置的 65536 字节 SRAM 内。日志开关关闭分支的主机编译通过。日志生产模块与 HEX/CSV 工具测试通过；原陀螺仪全量有符号数据解析/串口错误恢复测试和屏幕发送测试（179722 次断言）仍通过。原有四份被修改文件可移除新增日志片段还原修改前字节；其他已有控制文件逐字节保持。
