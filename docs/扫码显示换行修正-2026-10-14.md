# 扫码显示换行修正 · 2026-10-14

用户提供串口屏模拟器截图，要求收到 `123+321+213+132` 后发送 `page0.t0.txt="123+321+\r213+132"`，在第二个加号之后换行并保留加号。

核对发现桌面“小车只加通信版本”的 `hardware/uart_5.c` 仍使用15字节原样显示；独立“屏幕融合完成版”已实现所需转义。本次只修改原工程 UART5 的扫码发送副本：在第8个原始字节之后插入 `0x5C,0x72`（反斜杠、r），TX 缓冲容量扩大2字节。没有发送实际 CR/LF，没有修改扫码接收、任务原始数组、模拟扫码配置、抓放、路线、运动参数或日志代码。融合版无需重复修改，保留其初始化/结果发送功能。

`tools/tests/test_scan_hmi_newline.py` 提取原工程实际发送和解析代码，验证完整指令、换行字节、缓冲长度、三个FF结束，以及发送中每一个字节边界收到另一组扫码后不打断当前指令，任务原始数据保持不变。原四组扫码解析测试与融合版屏幕测试同时通过。

原工程 Keil 增量编译通过：0错误、4条原有警告，生成新的 `PRJ/Objects/Template.hex`。修改后重新根据 map 生成了陀螺仪日志 SAVE 命令，地址保持原值。原工程除 `hardware/uart_5.c` 外的既有非构建文件均与修改前 SHA256 一致。本次未修改 HMI 文件、未烧录、未连接实物屏幕。
