# 物料连续 5 帧稳定锁定

仅影响模式 1～6，模式 7 的数字/圆定位、补光控制和颜色阈值不变。

## 行为

- 每帧使用真实检测到的物料外接矩形中心。前 4 帧不会输出有效目标。
- 同一颜色连续 5 帧的 X 极差和 Y 极差分别不超过 3 像素时，允许输出当前帧坐标。
- 超过容差时，从当前帧重新累计；丢失、检测间断或切换模式时清零。
- 锁定后仍检查最近 5 帧；不冻结旧坐标。跟踪失败不再返回旧目标，下一帧尝试全图重找。
- 无候选时原有空缓存跳帧机制仍保留。跳过检测的帧返回空结果，不计入连续帧数。
- 未锁定时屏幕显示 `dx:-- dy:--`，不画物料中心十字。锁定后显示偏移并画白色中心十字。
- 串口仍每 10 个处理帧发送一次原有 8 字节帧。未锁定时发 `AA 00 00 00 00 00 00 55`；锁定后在下一个发送时机发 `found=1` 和当前偏移。
- 锁定丢失在相机端本帧生效，但主控收到 `found=0` 要等下一次 10 帧发送时机；没有额外即时包。

## 可调参数

在本工程 `config.py` 中修改，修改后重启：

```python
COLOR_STABLE_FRAMES = 5
COLOR_STABLE_TOLERANCE_PX = 3
```

增大稳定帧数会延后有效输出；减小容差会更严格，但实际抖动可能导致难以锁定。
3 像素是试用值，不是实测标定结果。帧数不是固定时间，5 帧所占时间随实际 FPS 改变。

## 部署和上板检查

1. 在 MaixVision 打开整个比赛项目，上传所有运行文件，包括新增的 `target_stability.py`。`app.yaml` 已加入此文件。
2. 原 `dist/maix-gc-v4.12.5.zip` 是旧包，本次没有更新。不要直接安装旧包；如需安装包，请重新打包。
3. 先禁止小车/机械臂实际动作，再发送模式 1～6。移动物料时，检查屏幕不出有效坐标、串口 `found=0`。
4. 停稳后检查出现白色十字和坐标，并收到原协议的有效帧；左右上下移动检查偏移方向。
5. 移走物料，检查坐标消失，下一个发送周期的 `found=0`；新物料进入同一位置后必须重新稳定。
6. 连续测试三次物料转入/停稳/移走，不能让上一个物料的旧坐标提前触发下一次抓取。
7. 测试切换颜色和切换 0/7 后再返回颜色模式，必须重新累计；模式 7 不经过本稳定门控。

主控仍负责物料顺序和抓取完成状态。稳定期间会重复发有效帧，不是每件只发一次；主控不能把每个 `found=1` 都当成新的抓取任务。
重复发送当前模式号不视为换模式，不会不断清空稳定计数；若需主动重置，可先切模式 0 再切目标颜色。

## 已知限制

- 判断的是图像中心稳定，不能证明物料自身停止旋转，也不能区分中心非常接近且没有可见间断的同色物料。
- 极慢移动若最近 5 帧的位移始终落在容差内，仍可能通过；若实测存在此情况，应收紧容差或延长观察窗口。
- 保留原有候选筛选和 ROI 策略，没有增加物料身份跟踪或修复颜色误检。稳定的误检也可能通过门控。
- 检测到的是可见颜色区域的外接矩形中心，不是物理测量中心；遮挡、反光仍会影响坐标。
- 本地测试使用模拟硬件，只验证控制逻辑、缓存和编码；实际相机 FPS、检测抖动和串口电气通信均待设备验证。
